# godot-player-kimi

Kimi code 的特别之处在于视频上下文，玩游戏的能力理应更强，可惜的是我们没有看到有人将这点充分发挥。
本插件将 Kimi 玩游戏的能力进一步补强，目的是达成游戏制作的闭环。

## 让 AI 玩家 接近 人类玩家  

AI 玩家和人类玩家跑的是同一个闭环：`按下键盘 → 游戏反馈 → 思考 → 再输入`。区别只在机能——
AI 的环上有四处先天缺陷，装置的每个观察类组件都在给其中一处打补丁：

| AI 的缺陷 | 补足手段 | 组件 |
|---|---|---|
| 视频有效采样仅 ~2–4fps，60fps 画面只能看到 ~5% | 帧数不够就**慢放** | 慢放/逐帧重打包 |
| 像素理解给不出精确数值，且部分状态根本不渲染（HP、内部标志位） | 看不准就用**精确数值**：游戏主动上报，顺带覆盖"看不见" | 逐帧遥测 JSONL |
| 时间理解能力不够，难以一一对应操作与反馈 | 做**一一数值对应**：给每张画面烧上帧号坐标 | HUD 帧号烧录 |
| 思考慢，游戏却瞬息万变 | 想得慢就**让游戏等 AI**：游戏常态暂停，每个决策点等模型 | 回合制主循环 |

我们用四个补偿器来让 AI 玩家 接近 人类玩家。
不过注意，这些补偿需要游戏源码才能上（装置要装进游戏工程里；只有导出成品的游戏不行）。

## 任何游戏都能玩、不用折腾

- 输入一律走 **Godot 官方输入通道** `Input.parse_input_event` 注入：action（InputMap 动作）、
  key（物理键码，适配 `_unhandled_input` 路线）、click（视口坐标鼠标）三通道，
  外加 `call` 兜底（直调节点方法，如菜单按钮 `emit_signal("pressed")`）与 `ui_dump` 内省。
  游戏怎么用标准输入，装置就能怎么玩——**不需要逐游戏适配**。
- 装置 = **一个 autoload 脚本（pilot.gd）+ 一个 bash 运行器（run.sh）**，零依赖，
  拷进任意 Godot ≥4.4 项目、注册 autoload 即用。

上限：有些场景是需要瞬间反应的，AI 回合制的玩法反应不过来——解法是把人类的条件反射编译成引擎内**反射规则**（AI 写条件触发、引擎每帧执行），已立项、格式后置。

## 主要模式

| 用法 | 说明 | 配方卡 |
|---|---|---|
| AI 试玩 | AI 自己玩游戏。当然，你也可以要求把窗口放出来你看它玩，也能随时插手，指指点点，AI 能分清你的操作和他自己的操作 | `ai-playtest` |
| 人玩 AI 看 | 用于告诉 AI ，你指的是什么，具体是哪些动作有问题，哪些操作没有得到正确的游戏反馈 | `review-demo` |

人和 AI 一起玩适合本来就回合制的游戏（棋牌、策略）；实时对战里人得陪着等 AI 思考，你会等疯的。

## 快速开始

把链接给 Kimi 让他帮你安装插件，之后就可以让他玩自己的游戏了。

## 仓库结构

```
kimi.plugin.json      插件清单
skills/               godot-pilot-rig（装置手册，唯一权威参考）
                      ai-playtest / review-demo（薄配方卡）
                      godot-docs（文档包查阅法）
assets/pilot/         试玩装置：pilot.gd + run.sh
assets/docs/          钉版文档包（管线产物，勿手改）
tools/                文档管线
```
